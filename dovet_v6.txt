── DOCX FILES ───────────────────────────────────────────────────────────

NAME ENFORCEMENT: At the very top of the Node.js script, declare:
  const STUDENT = 'Jack';  // ← replace with actual STUDENT_NAME value
Use STUDENT everywhere — in template literals, in Paragraph text, in
table cells. Never write the student name as a literal string anywhere
else in the script.

Use npm package: docx
Install: npm install docx

Critical docx rules:
  - ShadingType: always use CLEAR — never SOLID (SOLID renders black)
  - Table widths: always WidthType.DXA — never PERCENTAGE
  - Column widths: must sum exactly to the table width
  - PageBreak: must be wrapped inside a Paragraph element
  - Never use \n in text — use separate Paragraph elements instead
  - Page margins: top:720, bottom:720, left:900, right:900 (DXA)
  - Usable page width = 9360 DXA (A4 with above margins)

Run the generated script with: node script.js
Output file to: /mnt/user-data/outputs/[filename]

── HTML FILES ────────────────────────────────────────────────────────────

NAME ENFORCEMENT (runtime capture):
At the top of the <script> block declare:
  var STUDENT_NAME = '';
Populate it only after the student submits the name-entry step:
  STUDENT_NAME = document.getElementById('nameInput').value.trim();
  if (!STUDENT_NAME) { /* show error, stop */ return; }
Never write a literal student name anywhere in HTML markup or JS.
Every element showing the name must be set via .textContent or
string concatenation using the STUDENT_NAME variable at runtime.

Other HTML rules:
  - All CSS must be in a single <style> block inside the file
  - No external CSS. No external JS except the EmailJS CDN
  - All question data: var Qs = [/* JSON array */];
  - All message arrays: var CORRECT_MSGS = [...]; var WRONG_MSGS = [...];
  - Use var throughout — not let or const — for maximum compatibility
  - Close script tags as <\/script> inside string literals to avoid
    premature tag closure
  - If SOUND_EFFECTS = off, omit all audio code entirely
  - If TIMER_SECONDS = 0, omit all timer code and the timer display

── QUESTION DATA ─────────────────────────────────────────────────────────

For large datasets: write question data to a separate data.js file using
module.exports, then require() it in the builder script. This avoids
shell argument size limits.

Example:
  // data.js
  const MON = [...]; const TUE = [...]; // etc.
  module.exports = { MON, TUE, WED, THU, FRI };

  // builder.js
  const { MON, TUE, WED, THU, FRI } = require('./data.js');
