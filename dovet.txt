── DOCX FILES ──────────────────────────────────────────────────────────

⚠️  NAME ENFORCEMENT: Before writing any docx script, declare the
student name as a constant at the very top of the script:
  const STUDENT = 'Jack';  // ← use the actual STUDENT_NAME value
Then use STUDENT everywhere in the script — in strings, in
template literals, in Paragraph text — never write the name literally.
This guarantees the correct name appears in every cell and paragraph.

Use npm package: docx
Install: npm install docx

Critical rules:
  - ShadingType: always use CLEAR, never SOLID (SOLID renders black)
  - Table widths: always WidthType.DXA, never PERCENTAGE
  - Column widths: must sum exactly to table width
  - PageBreak: must be inside a Paragraph element
  - Never use \n — use separate Paragraph elements
  - Page margins: top:720, bottom:720, left:900, right:900 (DXA)
  - Usable page width = 9360 DXA (A4 with above margins)

Write the full Node.js script and run it with: node script.js
Output to: /mnt/user-data/outputs/[filename]

── HTML FILES ───────────────────────────────────────────────────────────

⚠️  NAME ENFORCEMENT (RUNTIME CAPTURE — see QUIZ NAME CAPTURE RULE):
Do NOT declare STUDENT_NAME as a hardcoded literal anywhere in the
script. Instead, at the top of the <script> block declare it empty:
  var STUDENT_NAME = '';
Populate it only once the student submits the name-entry step (welcome
screen item 2):
  STUDENT_NAME = document.getElementById('nameInput').value.trim();
  if (!STUDENT_NAME) { /* show the "type your name" error, stop here */ }
Then use STUDENT_NAME everywhere in the JavaScript — in welcome messages,
reaction messages, milestone messages, results screen text, email payload,
report text, and retry button label — always reading from this variable,
never from a literal string. This guarantees the SAME html file works
correctly no matter which student opens it and types their name in.

Also apply this to the HTML body: no static text anywhere in the
document should contain a literal student name. Any element that needs
to show the name must be populated by JavaScript after name capture
(e.g. innerText/textContent assignment), never written directly into
the HTML markup.

All CSS must be inline in a <style> block inside the HTML file.
No external CSS files. No external JS files except EmailJS CDN.
All question data must be JSON.stringify'd into a var Qs= declaration.
All messages (correct/wrong) must be arrays of strings.
Use var not let/const for maximum browser compatibility.
Script tag: use <script> ... <\/script> to avoid closing tag issues.

── QUESTION DATA ────────────────────────────────────────────────────────

For very large question datasets: write the question data to a
separate .js file (data.js) using module.exports, then require()
it in the HTML builder script. This avoids bash argument size limits.

Example:
  // data.js
  const MON = [...]; const TUE = [...]; ...
  module.exports = { MON, TUE, WED, THU, FRI };

  // builder.js
  const { MON, TUE, WED, THU, FRI } = require('./data.js');
